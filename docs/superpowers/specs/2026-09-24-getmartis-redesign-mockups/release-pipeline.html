Release e site tornam-se um único contrato

A tag só pode nascer quando o site estiver sincronizado, validado e associado ao mesmo commit do pacote.

1
Prepare release site Cria um PR no martis-docs; não cria a tag.
Validate packageVersão, CHANGELOG, release branch, build e CI verdes.
Sync contentPorta docs do pacote e detecta qualquer página desactualizada.
Generate release dataVersão, headline, requisitos, totais de testes e commit de origem.
Refresh product mediaPlayground seeded → capturas canónicas em desktop e mobile.
Open docs PRBuild, links, visual regression, a11y e freshness da comparação.
2
Publish release Executado apenas depois do PR do site estar aprovado e merged.
Cross-repo gateO manifest do site aponta para a versão e SHA exactos do package main.
Build immutable siteDocs, search index, comparação e dados públicos num único dist.
Create tag + releaseTag no merge commit verificado; notas extraídas do CHANGELOG.
Deploy same distPublicação Hostinger sem reconstruir artefactos diferentes.
Production proofSmoke de rotas, versão, contador, assets, docs e comparação.

Fontes geradas, nunca duplicadas à mão

Package manifestVersão, requisitos e SHA vêm do package.json/composer.json.
Release evidenceHeadline e notas vêm da secção correspondente do CHANGELOG.
Test reportsTotais Pest + Vitest vêm de relatórios machine-readable do CI.
PackagistDownloads total/mês/dia actualizados no build, com timestamp e fallback.

A tag é permitida quando…

  • package e site estão limpos e em main;
  • o manifest do site corresponde ao SHA da release;
  • sync, build, links, screenshots e acessibilidade passam;
  • a comparação foi revista dentro do prazo definido;
  • o dist final tem checksum registado.

A tag é recusada quando…

  • há versão ou documentação em drift;
  • os totais de testes foram editados manualmente;
  • faltam capturas obrigatórias após mudança visual;
  • uma fonte da comparação está indisponível ou expirada;
  • o site não passa o smoke local de release.
Entre releases: um workflow diário actualiza apenas o snapshot de downloads do Packagist e volta a publicar se o número mudou. O site mostra “updated …” e nunca depende da API no browser do visitante.
